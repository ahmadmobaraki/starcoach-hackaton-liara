# سناریوی ویدئوی دمو (حدود ۵ دقیقه)

> هدف: نشان دادن یک چرخه‌ی واقعی از درخواست کاربر تا انتخاب پلن، تأیید، استقرار، پایش، تشخیص و اقدام اصلاحی — به‌همراه MCP به‌عنوان خروجی قابل‌استفاده برای سایر Agentها.
>
> نسخه‌ی کوتاه ۳ دقیقه‌ای با متن ضبط در [video-script.md](../video-script.md) آمده است.

## چک‌لیست قبل از ضبط

1. `.env` کامل است: `LIARA_API_KEY`، `LLM_API_KEY`، `LLM_MODEL`، `APP_URL`.
2. `npm install && npm run dev` اجرا شده و صفحه باز است.
3. حساب لیارا اعتبار کافی دارد (برای ساخت یک برنامه‌ی `small-g2` یا `standard-base-g2`).
4. فایل `demo-site.tar.gz` ساخته شده است:
   ```bash
   tar -czf demo-site.tar.gz -C demo/sample-site .
   ```
5. یک پنجره‌ی Claude Desktop یا Cursor با MCP راهبر باز است (برای بخش پایانی).
6. اگر حساب اعتبار ندارد، از یک پروژه‌ی موجود استفاده کنید و بخش «استقرار» را با پیش‌نمایش تأیید نشان دهید؛ اما ویدئوی واقعی با استقرار امتیاز بیشتری می‌گیرد.

---

## ۰:۰۰–۰:۴۰ | مسئله

**روی صفحه بگویید:**

> «یک صاحب سایت غیرفنی می‌خواهد سایتش را روی لیارا بالا بیاورد. نمی‌داند چه پلنی بخرد، سورس را چطور آپلود کند، و اگر سایت ۵۰۰ داد چه کار کند. راهبر یک همکار فنی فارسی‌زبان است که این مسیر را از صفر طی می‌کند.»

صفحه‌ی خالی پنل را نشان دهید: چت، پیشنهادهای شروع، و ریلی که وضعیت سرویس را نشان می‌دهد.

---

## ۰:۴۰–۱:۳۰ | انتخاب پلن با قیمت زنده

**کلیک:** «چه پلنی مناسبه؟»

**تایپ:**

> «برای یک سایت Next.js با ترافیک متوسط و بدون دیتابیس، بودجه‌ی ماهانه ۲ میلیون تومان، چه پلنی مناسب است؟ گزینه‌ها را با قیمت مقایسه کن.»

**چه اتفاقی می‌افتد:**

- راهبر `liara_recommend_plan` را صدا می‌زند.
- کارت پلن با قیمت زنده، RAM/CPU/دیسک، بسته‌ی امکانات و گزینه‌ی ارزان‌تر نمایش داده می‌شود.
- توضیح دهید که قیمت بسته، قیمت کل است و مقایسه بر اساس داده‌ی واقعی حساب است.

**بگویید:** «این کارت از `/v1/me` خوانده شده؛ هیچ قیمتی hardcode نشده.»

---

## ۱:۳۰–۲:۴۰ | ساخت برنامه و استقرار

**کلیک:** «انتخاب همین پلن» یا تایپ:

> «همین پلن را انتخاب می‌کنم. یک برنامه‌ی جدید به نام `raahbar-demo` بساز و بعد فایل نمونه را مستقر کن.»

**چه اتفاقی می‌افتد:**

- راهبر پیشنهاد قابل‌تأیید (`liara_prepare_action` با `create_app`) می‌سازد.
- کارت تأیید را نشان دهید: تغییرات، هزینه‌ی ماهانه، برگشت‌ناپذیری و دکمه‌ی «تأیید و اجرا».
- تأیید کنید. نتیجه و وضعیت پروژه بررسی می‌شود.
- فایل `demo-site.tar.gz` را با دکمه‌ی آپلود (گیره‌ی کاغذ) آپلود کنید.
- راهبر پیشنهاد استقرار می‌سازد؛ دوباره کارت تأیید را نشان دهید و تأیید کنید.
- ریل استقرار (ساخت → آپلود → بیلد → انتشار → دامنه) پر می‌شود و لاگ بیلد/وضعیت release نمایش داده می‌شود.
- در پایان، آدرس پیش‌فرض و وضعیت سلامت را نشان دهید.

**بگویید:** «دو اقدام حساس بود؛ هر دو فقط بعد از تأیید من اجرا شدند. خود مدل هیچ راهی برای تأییدکردن ندارد.»

---

## ۲:۴۰–۳:۴۰ | پایش و عیب‌یابی

**تایپ:**

> «سایتم کند شده؛ منابع و لاگ‌ها را بررسی کن و بگو مشکل از پلن است یا از برنامه.»

**چه اتفاقی می‌افتد:**

- `liara_diagnose_app` اجرا می‌شود.
- کارت تشخیص: CPU، حافظه، دیسک، تعداد خطا، وضعیت release، یافته‌های رتبه‌بندی‌شده با شاهد و درصد اطمینان.
- اگر داده‌ی کافی نبود، صادقانه می‌گوید و قدم بعدی را پیشنهاد می‌دهد.
- اگر اقدام اصلاحی (ری‌استارت/تغییر پلن) پیشنهاد شد، کارت تأیید را نشان دهید. برای دمو، ری‌استارت را تأیید کنید (کم‌هزینه و سریع) و نتیجه‌ی بررسی بعد از اجرا را نشان دهید.

**نکته:** اگر سایت واقعاً کند نیست، می‌توانید یک پروژه‌ی نمونه با مصرف بالا بسازید یا سناریوی خطای ۵۰۰ را با لاگ مصنوعی توضیح دهید. از ادعای تشخیص بدون شاهد خودداری کنید.

---

## ۳:۴۰–۴:۳۰ | دامنه و تحویل کار دستی

**تایپ:**

> «می‌خواهم دامنه‌ام را وصل کنم؛ مراحل ایرنیک را بگو.»

**چه اتفاقی می‌افتد:**

- راهبر `liara_get_guide` با موضوع `domain-irnic` را می‌خواند.
- کارت راهنما: کارهایی که راهبر انجام می‌دهد، کارهایی که کاربر باید انجام دهد، و مراحل.
- دکمه‌ی «انجام دادم؛ بررسی کن» را نشان دهید و کلیک کنید.
- راهبر `liara_check_domain` را صدا می‌زند و می‌گوید هنوز PENDING است یا تایید شده؛ قدم بعدی را می‌دهد.

**بگویید:** «راهبر ادعا نمی‌کند رکورد ایرنیک را تغییر داده؛ دقیقاً می‌گوید چه کاری خارج از API است، و بعد از گزارش من نتیجه را بررسی می‌کند.»

---

## ۴:۳۰–۵:۰۰ | MCP برای Agentهای دیگر

پنجره‌ی Claude Desktop/Cursor را نشان دهید که MCP راهبر به آن وصل است.

**نشان دهید:**

- لیست ابزارها (۲۴ ابزار).
- فراخوانی `liara_recommend_plan` یا `liara_diagnose_app`.
- توضیح دهید که پنل هم از همان MCP استفاده می‌کند؛ هیچ منطق تکراری وجود ندارد.
- اگر یک ابزار حساس را صدا زدید، `approveUrl` را نشان دهید: همان کارت تأیید پنل برای کلاینت خارجی هم باز می‌شود.

**جمع‌بندی:**

> «راهبر یک چت‌بات نیست؛ یک لایه‌ی عامل (agentic) روی APIهای واقعی لیارا است: گزینه می‌دهد، بهترین را پیشنهاد می‌کند، کارهای مجاز را با تأیید انجام می‌دهد، و کارهای خارج از API را با راهنمای دقیق به کاربر می‌سپارد و نتیجه را بررسی می‌کند.»

## نقشه‌ی امتیازدهی

| معیار | کجای دمو |
|---|---|
| اتصال به API لیارا | پلن زنده، ساخت برنامه، آپلود، release، لاگ، متریک |
| راه‌اندازی و دیپلوی | بخش ۱:۳۰–۲:۴۰ |
| مدیریت سرویس | ری‌استارت/تغییر پلن در بخش ۲:۴۰ |
| تحلیل لاگ و تشخیص | کارت تشخیص با شاهد |
| ارائه راهکار و بررسی نتیجه | کارت تأیید + `liara_verify_project` |
| UX | چت فارسی RTL، کارت‌ها، ریل استقرار، تأیید واضح |
| امنیت | دو مرحله‌ای، تأیید انسانی، ماسک env، redaction، audit |
| محدودیت API | کارت راهنما و متن صریح درباره ایرنیک/پرداخت/SSH |
| MCP | بخش ۴:۳۰ |

## اگر حساب اعتبار ندارد

- بخش پلن و کارت تأیید را نشان دهید و بگویید «اجرای واقعی به اعتبار حساب نیاز دارد؛ راهبر خطای ۴۰۲ را به‌عنوان محدودیت پرداخت توضیح می‌دهد.»
- از یک پروژه‌ی موجود (اگر دارید) برای بخش پایش/تشخیص استفاده کنید.
- ویدئو را با نمایش MCP و مستندات کامل کنید. صداقت درباره‌ی محدودیت، بهتر از ادعای انجام عملیات نیست.
